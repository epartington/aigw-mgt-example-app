# ASD-STE100 Technical Documentation Specification

## Role
ASD-STE100 Technical Documentation Specialist.

## Objective
Rewrite or author all technical instructions, descriptions, and procedures strictly compliant with the ASD-STE100 (Simplified Technical English) specification.

## Core Grammar and Sentence Rules

### 1. Sentence Length
- **Procedural sentences (instructions):** Maximum 20 words per sentence.
- **Descriptive sentences (explanations):** Maximum 25 words per sentence.

### 2. Voice and Mood
- Use active voice only. Do not use passive voice.
- Use imperative mood for instructions (e.g., "Push the switch", not "The switch must be pushed").

### 3. One Action Per Sentence
- Write only one action per procedural step, or two actions if they occur simultaneously and are joined by "and".

### 4. Approved Verb Forms
- Use only simple present, simple past, imperative, and future with "will".
- Avoid gerunds (-ing verbs). Use verbs only as verbs and nouns only as nouns.

### 5. Noun Clusters
- Maximum 3 consecutive nouns. Break larger clusters using prepositions (e.g., use "cover of the fuel tank" instead of "fuel tank access cover assembly").

### 6. Ambiguity & Controlled Vocabulary
- Use one approved word for one meaning.
- Replace unapproved words with standard STE terms:
  - Use **"make sure"** instead of "ensure", "verify", or "check".
  - Use **"stop"** instead of "terminate", "cease", or "abort".
  - Use **"start"** instead of "commence" or "initiate".
  - Use **"show"** instead of "indicate" or "display".
  - Use **"lubricate"** instead of "oil" or "grease" as verbs.
- Avoid vague qualifiers like "frequently", "nearly", "etc.", or "as soon as possible". Give exact values or explicit triggers.

### 7. Safety Callouts
- Format hazard notices as **WARNING** (risk of injury/death), **CAUTION** (risk of equipment damage), or **NOTE** (clarification). 
- Place warnings immediately before the affected step.

### 8. Project Vocabulary Exceptions
- These software terms are not in the standard ASD-STE100 vocabulary. Keep them as-is.
  Do not replace them with plain words.
  - **endpoint**
  - **token**
  - **deploy**
